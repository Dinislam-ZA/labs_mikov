# Сервер приложения для управления цехами и датасетами

Серверная часть приложения для управления цехами и датасетами, включающая API для аутентификации, работы с пользователями, цехами и датасетами.

## Технологии

- Node.js
- Express
- better-sqlite3
- JSONWebToken
- dotenv

## Установка и запуск

1. Установите зависимости:

```bash
npm install
```

2. Создайте базу данных:

```bash
node initDB.js
```

3. Запустите сервер в режиме разработки:

```bash
npm run dev
```

Или в обычном режиме:

```bash
npm start
```

По умолчанию сервер будет запущен на порту 5000. Вы можете изменить порт в файле `.env`.

## Структура проекта

- `server.js` - главный файл сервера
- `db.js` - модуль для работы с базой данных
- `initDB.js` - скрипт для инициализации базы данных
- `middleware/` - промежуточные обработчики
  - `auth.js` - для аутентификации и проверки прав
- `routes/` - маршруты API
  - `auth.js` - маршруты для аутентификации
  - `datasets.js` - маршруты для работы с датасетами
  - `workshops.js` - маршруты для работы с цехами
  - `users.js` - маршруты для работы с пользователями

## API Endpoints

### Аутентификация

- `POST /api/auth/login` - вход в систему
- `GET /api/auth/me` - получение информации о текущем пользователе

### Пользователи

- `GET /api/users` - получение всех пользователей (только для администратора)
- `GET /api/users/:id` - получение пользователя по ID (только для администратора)
- `POST /api/users` - создание нового пользователя (только для администратора)
- `PUT /api/users/:id` - обновление пользователя (только для администратора)
- `DELETE /api/users/:id` - удаление пользователя (только для администратора)

### Цеха

- `GET /api/workshops` - получение всех цехов
- `GET /api/workshops/:id` - получение цеха по ID
- `POST /api/workshops` - создание нового цеха (только для администратора)
- `PUT /api/workshops/:id` - обновление цеха (только для администратора)
- `DELETE /api/workshops/:id` - удаление цеха (только для администратора)

### Датасеты

- `GET /api/datasets` - получение всех доступных датасетов
- `GET /api/datasets/:id` - получение датасета по ID
- `POST /api/datasets` - создание нового датасета (только для администратора)
- `PUT /api/datasets/:id` - обновление датасета (различные права для разных ролей)
- `DELETE /api/datasets/:id` - удаление датасета (только для администратора)

## Роли пользователей

- `0` - начальник цеха
- `1` - диспетчер
- `2` - администратор

## Тестовые учетные записи

- Администратор: `admin` / `123`
- Диспетчер: `dispatcher` / `123`
- Начальник цеха 1: `workshop1` / `123`
- Начальник цеха 2: `workshop2` / `123`
